# 15 验收清单

> 版本：`v0.1`（P0 设计基线）
> 最后更新：2026-09-20
> 责任人：两人共同
> 用途：作为“进入下一阶段 / 最终提交”的判定依据。

## 1. 进入编码的门禁

- [ ] 项目章程与 MVP 范围已确认（01）；
- [ ] Android 能力边界表已完成（02）；
- [ ] 主演示场景已确定（后台读取剪贴板/位置 + 网络行为解释）；
- [ ] 系统架构与模块边界已完成（05、06）；
- [ ] 事件模型与规则契约已完成（07、09、10）；
- [ ] 真实/沙箱模式标识方式已约定。

## 2. 进入真实数据接入的门禁

- [ ] 模拟事件可驱动页面和规则；
- [ ] 本地事件库结构稳定；
- [ ] 页面不直接依赖单一 Android API；
- [ ] 失败和未知状态有明确 UI。

## 3. 进入冲奖演示打磨的门禁

- [ ] VPN、Usage Access 和 Demo App 在同一设备可重复运行；
- [ ] 至少一个合理场景和一个不匹配场景可复现；
- [ ] 处置后有可观察的复查结果；
- [ ] 所有结论都能区分事实、推断和不可观测部分。

## 4. 产品与软件

- [ ] APK 可安装、可启动、可完成核心演示；
- [ ] 核心流程可现场完整运行；
- [ ] 断网时至少能运行本地监测、事件查看和基础摘要；
- [ ] 公网增强服务地址、端口、账号已验证；
- [ ] 演示数据与真实数据有明确区分。

## 5. 设计文档

- [ ] 有需求分析、用户场景、设计思路和功能模块；
- [ ] 有系统架构、数据模型、权限说明与隐私安全设计；
- [ ] 有全生命周期步骤、操作说明与测试结果；
- [ ] 已填平台、版本、工具、AI 模型与 AI 辅助代码比例；
- [ ] 已说明原创部分与第三方开源代码/素材/模型来源；
- [ ] PDF 无乱码、截断、空白异常或不可读图片。

## 6. 作品简介与截图

- [ ] 简介不超过 800 字；
- [ ] 恰好 3 张核心功能截图；
- [ ] 每张为 JPG/PNG 且 ≤ 1 MB；
- [ ] 截图不含真实个人信息、密钥或测试账号。

## 7. 源码、安装包与视频

- [ ] 源代码可编译，依赖版本与构建步骤齐全；
- [ ] APK 与源码版本号一致；
- [ ] 视频为 MP4，≤ 5 分钟、≤ 150 MB，含背景/核心流程/技术亮点/实际运行画面；
- [ ] 打包目录无 `.env`、私钥、真实用户数据或无关键时文件。

## 8. 最终一致性

- [ ] 任何提交材料与 APK 实际功能不一致，都不提交。
