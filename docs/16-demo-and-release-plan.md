# 16 演示与发布方案

> 版本：`v0.1`（P0 设计基线）
> 最后更新：2026-09-20
> 责任人：两人共同

## 1. 固定演示环境

| 项 | 要求 |
|---|---|
| 演示设备 | 固定一台测试机，记录品牌、型号、Android 版本（≥ Android 10） |
| 系统版本 | 固定，不再中途更换 |
| 网络 | 核心流程离线可跑，公网增强（AI）可选 |
| 授权 | 提前完成通知、Usage Access、VPN 授权 |
| Demo App | 随主 App 一起安装，场景可重置 |

## 2. 现场授权步骤

1. 打开主 App → 隐私说明页；
2. 授予通知权限；
3. 跳转设置授予 Usage Access；
4. 授予 VPN 连接请求；
5. 安装并启动 Demo App，选择演示场景。

## 3. 主演示故事线（约 3 分钟）

```text
异常发生 -> 场景判断 -> 因果解释 -> 执行处置 -> 复查变化
```

步骤：

1. 用户复制一段测试验证码（演示数据）；
2. 计算器 Demo App 进入后台并触发后台读取剪贴板/位置 + 网络请求的受控事件；
3. 哨兵弹出告警，显示时间、App、行为、前后台状态；
4. 系统判断与计算器场景不匹配，显示风险分、置信度、证据来源；
5. 展开隐私因果链：后台状态 → 读取剪贴板/位置 → 网络请求 → 可能影响 → 建议；
6. AI 将结构化证据解释为普通用户能理解的一段话，不新增事实；
7. 用户执行建议：阻断域名/App 或跳转系统设置限制后台活动；
8. 系统进入复查模式，展示处置前后行为数量变化；
9. 查看事件证据卡片与（P1）每日摘要/PDF 报告。

## 4. 离线与异常降级分支

| 场景 | 演示处理 |
|---|---|
| 断网 | 展示本地监测、事件查看、基础摘要；说明 AI 走模板兜底 |
| 拒绝 VPN | 进入演示沙箱模式，展示演示事件并标注 |
| VPN 被回收 | 展示“监测已暂停”提示与恢复入口 |
| UID 无法归属 | 展示“无法归属”，强调诚实边界 |
| 无域名 | 展示 IP + 推测类别，不强行生成域名结论 |

## 5. 答辩要主动说明

- 哪些数据来自 Android 官方能力、哪些来自用户授权网络元数据、哪些是受控演示数据；
- 为什么不能简单把一次权限访问认定为恶意；
- 场景推理如何降低误报；
- AI 如何被证据和规则约束；
- 评测集如何构造、目前有哪些失败案例和改进方向。

## 6. 发布与版本一致性

- 冻结版本号（APK、源码、文档、截图、视频一致）；
- 完成 Demo App 安装与场景重置脚本；
- 完成异常演示分支演练；
- 打包源代码、构建说明、APK；
- 清理密钥、测试账号、真实个人信息与临时文件。

## 7. 最终提交材料

| 材料 | 要求 |
|---|---|
| 作品简介 | ≤ 800 字 |
| 设计文档 PDF | 覆盖需求、设计、模块、工具、全周期、测试 |
| 源代码压缩包 | 依赖版本与构建说明齐全 |
| Android 安装包 APK | 与源码版本一致 |
| 演示视频 MP4 | ≤ 5 分钟、≤ 150 MB |
| 3 张核心截图 | JPG/PNG，每张 ≤ 1 MB |
| 最终提交检查表 | 见 15 |
