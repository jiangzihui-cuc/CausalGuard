## 2. 分层与职责

| 层 | 职责 | 不允许 |
|---|---|---|
| 采集层 | 封装 Android 原始 API，输出标准事件 | 页面直接调用 Android API |
| 本地数据层 | 存取事件、画像、规则、处置；证据关联；去重 | 规则直接修改原始事件 |
| 洞察服务层 | 场景判断、分类、评分、聚合、建议、AI | 自行发明事实；修改原始事件 |
| 展示层 | 渲染页面，绑定 ViewModel 状态 | 反向写数据库、直接读原始 API |

## 3. 数据流

```text
采集层(真实/演示)
  -> 适配成统一 PrivacyEvent 写入事件库
  -> 证据关联引擎建立 EvidenceLink
  -> 风险规则引擎读事件 + 画像 + 上下文 -> RiskAssessment
  -> 因果链构建器 -> 解释层(模板/AI)
  -> 处置层(建议/阻断) -> 处置记录
  -> 复查层对比处置前后事件
```

页面只消费 ViewModel 暴露的 State，状态由洞察服务层产出。

## 4. 模块依赖方向

```text
展示层 ──> 洞察服务层 ──> 本地数据层 ──> 采集层
               │              │
               └────契约接口────┘
```

依赖只能自顶向下，采集层不反向依赖展示层。规则引擎依赖事件契约和场景知识库，但不依赖具体 Android 实现。

## 5. 架构决策记录

| 决策 | 选择 | 理由 |
|---|---|---|
| 语言 | Kotlin | 团队熟悉、与 Android 官方一致 |
| UI | Jetpack Compose 或 XML（冻结一种） | 避免混用导致返工 |
| 状态管理 | ViewModel + StateFlow | 页面与逻辑解耦 |
| 数据库 | Room / SQLite | 类型安全、便于迁移 |
| 网络观测 | VpnService + 成熟转发核心 | 不从零实现 TCP/IP 栈 |
| 依赖注入 | Hilt 或手工构造（冻结一种） | 便于测试 |
| AI | 可选接口，本地模板兜底 | 核心不依赖在线 |
| 转发核心 | 成熟用户态方案 | 降低断网风险 |

## 6. 真实/演示模式标识

- 每类事件在数据模型带 `source` 与 `isDemo` 字段；
- 界面 / 文档 / 答辩统一区分真实观测、授权观测、演示真值；
- 演示事件不得与其他事件在展示上混淆。

## 7. 验收检查

- [ ] 每个模块有输入、输出、责任人；
