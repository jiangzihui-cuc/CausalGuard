## 1. 项目基本信息

| 项 | 内容 |
|---|---|
| 项目名称 | 隐私因果哨兵 Privacy Sentinel |
| 仓库名 | CausalGuard |
| 参赛方向 | 智能网联与智能终端赛道——移动互联网人工智能应用程序开发 |
| 目标用户 | 对隐私有关注但不理解网络日志与 SDK 名称的普通用户；需要快速检查设备的用户；安全演示/教学场景 |
| 参赛目标 | 提交可运行完整软件系统，并在决赛现场演示完整闭环 |

## 2. 项目定位（一句话）

**隐私因果哨兵是一款运行在 Android 移动设备上的隐私行为解释与处置智能体：结合 App 使用场景、敏感数据访问、网络元数据和用户授权状态，判断行为是否合理，构建可追溯的隐私因果链，并指导用户完成处置和复查。**

## 3. 冲奖版核心价值

不定位为普通权限统计工具，而是**面向使用场景推理的移动端隐私行为解释与处置智能体**。

核心闭环：

```text
采集行为证据
  -> 判断是否符合当前场景
  -> 构建隐私因果链
  -> 解释风险和不确定性
  -> 给出可逆处置建议
  -> 复查处置后的行为变化
```

与 TrackerControl 类工具的差异：核心是“翻译 + 建议”，而不是“监控 + 拦截”。不把 tracker 名称和 IP 作为主要输出，而是翻译为可理解的隐私影响，聚合成场景化解释，并对应到具体系统设置操作。

## 4. 两种运行模式（必须严格区分）

### 4.1 真实观测模式

观察普通第三方 App 能真实提供的信号：

- App 包名、UID、版本和权限能力；
- 当前授权状态；
- 前后台和近期使用状态；
- VPN 观测到的网络连接、域名线索、目标 IP、端口和流量；
- 阻断规则是否生效；
- 处置后的行为变化。

### 4.2 演示沙箱模式

由团队控制 Demo App，提供准确真值：

- 前台合理访问位置；
- 后台延迟访问位置；
- 访问敏感数据但不联网；
- 不访问敏感数据但后台联网。

**两种模式必须在界面、数据模型、设计文档和答辩中明确区分。** 所有模拟事件显式标注“演示数据”，防止评审误认为是真实采集结果。

## 5. MVP 必须完成的功能（P0）

| 编号 | 功能 | 说明 |
|---|---|---|
| P0-1 | 首次授权引导 | 解释每项权限用途、拒绝后果和暂停监测方法 |
| P0-2 | App 能力画像 | 包名、UID、版本、声明权限、授权状态、场景类型 |
| P0-3 | Usage Access 使用上下文 | 前后台、近期使用、用户交互事件（缺失时降级） |
| P0-4 | VPN 网络元数据 | 目标 IP、端口、协议、时间、流量、UID 归属、域名线索 |
| P0-5 | 统一事件时间线 | 事件列表、详情、去重与频率聚合 |
| P0-6 | 5-10 条本地规则 | 必要通信/分析追踪器/高风险行为分类与场景判断 |
| P0-7 | 证据卡片 | 展示事实来源、证据等级、分类依据、置信度 |
| P0-8 | 域名/App 阻断 | 通过 VPN 阻断规则生效并记录 |
| P0-9 | 处置后复查 | 处置前快照 + 观察窗口 + 行为变化对比 |
| P0-10 | 4 个 Demo App 演示场景 | 提供可重复、可解释的行为真值 |

P0 详细需求见 [04-product-requirements.md](04-product-requirements.md)。

## 6. P0 / P1 / P2 优先级

| 优先级 | 范围 | 处理原则 |
|---|---|---|
| P0（必须做） | 上述 10 项，围绕“后台读取剪贴板/位置 + 网络行为解释”主案例 | 时间紧张时优先保证 P0 闭环 |
| P1（应该做） | 每日摘要、AI 解释、PDF 导出、更多场景类型、频率异常评分 | P0 稳定后再做，新增需变更评审 |
| P2（暂不做） | 更多平台、TLS 解密、无障碍监控、自动撤销权限、完整 TCP/IP 栈 | 首版明确排除 |

## 7. 首版绝对不做的内容（范围排除表）

- 不做 TLS 中间人解密；
- 不做无障碍服务监控其他 App 页面；
- 不承诺监控其他 App 每一次定位、相机、麦克风和通讯录调用；
- 不依赖 `AppOpsManager` 获取其他 App 的全局访问历史；
- 不自动撤销其他 App 的权限；
- 不从零开发完整 TCP/IP 协议栈；
- 不让大模型直接读取原始网络流量并自行判定是否泄露；
- 不在没有证据时使用“窃取”“恶意上传”等确定性措辞；
- 不同时适配多个移动平台。

## 8. 目标设备与演示环境

| 项 | 约束 |
|---|---|
| 系统基线 | Android 10 / API 29 及以上 |
| 语言 | Kotlin |
| 页面 | Jetpack Compose 或 XML，二选一，尽早冻结，不混用 |
| 本地数据 | Room / SQLite |
| 演示设备 | 固定一台已 root 无关的常规测试机，记录品牌、型号、Android 版本 |
| 网络 | 核心功能离线可用；公网增强功能（AI）可用但不作为核心依赖 |
| 现场降级 | 断网、VPN 被回收、授权拒绝、无法归属均有降级路径 |

## 9. 成功标准

**可以接受的：**

- 观测一个可获得的网络行为；
- 结合 App 使用上下文进行有限推理；
- 展示证据和不确定性；
- 执行一个可逆处置；
- 验证处置结果（或诚实输出“无法确认”）。

**不能接受的失败：**

- 承诺能实现但尚未验证的关键演示功能；
- 无法追溯来源的风险结论；
- 把推断结果冒充系统事实；
- 断网或拒绝授权导致闪退；
- 演示数据未标注。
